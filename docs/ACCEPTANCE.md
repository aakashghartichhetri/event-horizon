# Acceptance criteria and test matrix

This checklist describes what the **implemented** system must do, not future features. CTest uses the same sample data as the web interface and verifies the full vertical slice.

| Feature | Acceptance criteria | Automated verification | Manual verification |
|---|---|---|---|
| Exchange order matching | Buy/sell limit orders match best price and earliest arrival; fills price at resting order; partial matches/cancellations retain correct reservations; duplicate IDs/self-trades are rejected | `price priority and refund`, `FIFO`, `partial fill`, `reservations and cancel`, `invalid input`, `unique order IDs` in `tests/core_tests.cpp` | `event-horizon replay data/baseline.csv` |
| Accounting and settlement | Cash and shares remain conserved across participants and escrow; pending fills deliver neither asset early; settlement processes FIFO with optional capacity; outages block settlement without discarding escrow | `payment escrow`, `batch settlement FIFO`, `randomized conservation` in core tests; `tests/http_integration.py` | `payments_outage` shows $400 escrow; `settlement_throttle` shows 1 pending / $70 escrow |
| Failure mitigation and controls | Early recovery completes 3 trades, funded loan bridge is repaid, notional / price-band restrictions reject intended trades, cash lock prevents downstream orders | `funded bridge`, `liquidity reservation cascade`, `circuit breaker`, `notional limit`, `loans cannot spend reservations` | Compare `payments_outage`, `recovery`, `liquidity_bridge`, `liquidity_shock`, `circuit_breaker` |
| Deterministic agents and replay | Agent submits at most one order after funding; same CSV emits exactly matching JSON and balances; source line indicated on errors | `deterministic agent execution`, `deterministic JSON escaping`, `strict input parsing`, `parallel independent scenarios` | `agents` scenario; edit CSV and run custom replay twice |
| HTTP dashboard and export | Local server serves static UI and JSON endpoints; custom replay accepts raw CSV; unknown routes and oversized bodies fail safely; parallel requests remain isolated | `tests/http_integration.py`: all nine scenarios, 32 parallel requests, errors and input sizes; `node --check web/app.js` verifies JS syntax | Navigate scenarios in browser; compare; run custom; export JSON |
| Tooling and portability | Native GCC/Clang build, sanitizer runs, deterministic synthetic benchmark, Dockerfile/Compose and CI definitions exist | `ctest` on Debug, Release, Clang sanitizers; `benchmark 10000`; GitHub Actions matrix | `./scripts/start.sh`, `./scripts/test.sh`, `docker compose up --build` |

**Testing caveat:** A successful native build does not prove that the Docker image or hosted GitHub Actions jobs are passing. Run those separately after publishing; record their actual results. An interactive visual browser test also depends on a browser environment, though the HTTP static assets and JS syntax are included in CI-adjacent checks.
